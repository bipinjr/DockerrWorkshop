System prompt guides the model. Empty messages return 400. LLM failures return 502.

The same flow works three ways:

# 1. Local — uvicorn (port 8000) python3 main.py

# 2. Docker — containerized docker build -t agent:latest .
docker run -p 8000:8000 --env-file .env agent:latest

# 3. Vercel — serverless functions # Push to GitHub, connect to Vercel, set GROQ_API_KEY=gsk_...

# Call it from anywhere curl -X POST http://localhost:8000/agent -H 'Content-Type: application/json' -d '{"message":"Hello"}'

Deploy

Get it live

Push to GitHub, connect to a platform, add one environment variable, and you have a public URL.

V Vercel

This repo is already set up for Vercel. The api/ folder holds serverless functions; index.html is the static site.

  • Connect the GitHub repo in Vercel
  • Set GROQ_API_KEY as an environment variable
  • Deploy — get a .vercel.app URL
# Vercel project settings → Environment Variables GROQ_API_KEY=gsk_...

R Render

Web Service → connect the repo → Render detects the Dockerfile → add the key → deploy.

  • Set GROQ_API_KEY in Environment Variables
  • Dockerfile is enough — no build command needed
  • Get a .onrender.com URL
# Render dashboard → Environment GROQ_API_KEY=gsk_...

R Railway

New Project → Deploy from GitHub → Railway uses the Dockerfile → add the variable → deploy.

  • Add GROQ_API_KEY under Variables
  • Service listens on port 8000
  • Get a .railway.app URL
# Railway → Variables GROQ_API_KEY=gsk_...

The same codebase works everywhere. Vercel for serverless, Docker for containers, Render/Railway for managed hosting.
